# Studiotheca Public Project Charter

## Purpose

Studiotheca preserves public-facing studio identity studies, creative experiments, proposed games, and original supporting materials. It does not claim that conceptual work is a launched studio or shipped game. Game source stays in independent repositories.

## Publication boundary

Do not copy nonpublic conversations, transcripts, personal venting, confidential documents, credentials, internal prompts, private service endpoints, or unpublished private work into this archive. Write neutral professional descriptions; preserve the creative decisions without copying private conversational wording.

The boundary applies to files, images, metadata, filenames, commits, issues, tests, workflows, releases, and recoverable history. Public Git attribution is permitted, but it does not authorize exposure of otherwise private material.

## Creative integrity

Preserve numbered design versions, including rejected alternatives, rather than silently overwriting the past. Distinguish a working proposal, candidate, approved treatment, final master, and released product. Gallery entries must reference real, checked-in material. Record media origins, permissions, editability, and uncertainty before import. An image render is not an editable vector master.

Keep this archive independently usable without unpublished files or private dependencies. External project registry enrollment or cross-repository edits require explicit authorization separate from maintaining this archive.

## Maintenance

Follow repository scope, work directly on `main` by default, run `python3 scripts/validate.py`, and review new publication material for provenance and disclosure risk. The owner retains the choice of license; this charter does not amend MIT.
